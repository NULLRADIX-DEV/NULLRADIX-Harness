Writing rules for a question. The reader is an outsider: they know neither the ticket nor the code and still must be able to decide in two minutes.
- One question, one decision. Several related decisions become several questions; the later one refers to the earlier one with --depends <question>.
- Title: a question with a question mark, at most 80 characters, in the language of the domain, without a ticket number and without class names.
- Description (Markdown, at most 200 words) in these sections:
  **What it is about** - 2-3 sentences: what happens today and why that needs a decision;
  **Today** - up to 4 bullet points, described as behavior;
  **To decide** - one sentence;
  **Options** - one line per option: title - most important consequence;
  **Recommendation** - one sentence with the reason.
- Spell out abbreviations on first use; class and file names only if nothing is understandable without them.{{promptExtra}}
